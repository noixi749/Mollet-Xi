# Mollet Xi ~データ盗む君~ 一式

製作者 Naohisa Akiyama ／ アプリ 1.0.0

## 中身

| フォルダ・ファイル | 何か |
|---|---|
| `app/` | アプリ本体。5つのファイルを丸ごと https のサイトに置く |
| `firmware/MolletXi_CDI_Ign` | CDIの点火マイコン（Arduino Nano） |
| `firmware/MolletXi_CDI_Com` | CDIの通信マイコン（XIAO ESP32S3 か ふつうのESP32） |
| `firmware/MolletXi_Logger` | ロガー（XIAO ESP32S3 か ふつうのESP32） |
| `firmware/MolletXi_BenchTester` | 予備のNanoで作る、机の上で進角を確かめる道具 |
| `parts.html` | 部品リスト・配線表・組み立て順（claude.ai のページと同じ） |

## 1. アプリを置く（GitHub Pages）

Bluetooth と位置情報は https のページでしか動かないので、前の計算機と同じく GitHub Pages に置きます。

1. GitHub で新しいリポジトリを作る（例：`mollet-xi`、Public）
2. `app` の中の5つ（`index.html` `manifest.webmanifest` `sw.js` `icon-192.png` `icon-512.png`）をアップロード
3. Settings → Pages → Branch を `main`・`/(root)` にして Save
4. 数分で `https://noixi749.github.io/mollet-xi/` が開けます

前のリポジトリ `scooter-topspeed` の中に `mollet-xi` フォルダを作って入れても動きます（`…/scooter-topspeed/mollet-xi/`）。

## 2. インストール

- **Android**：Chrome で開く → 右上のメニュー →「アプリをインストール」
- **Windows**：Chrome か Edge で開く → アドレスバー右の「インストール」
- 一度開けば、電波の弱いサーキットでも本体は開けます（地図とピット通信はネットが要る）
- 初めて開いたら「サンプルで試す」で全部の機能を触れます
- 色は「設定 → 表示・色」。用意した7つの配色（昼間の白地・直射日光用もあり）から選ぶか、アクセント・背景・パネル・文字・良い／注意／危険の7色を自分で選んで名前をつけて保存。端末ごとに別の色にできます

## 3. CDI・ロガーをつなぐ

- 基本は Bluetooth。名前は `MolletXi-CDI` と `MolletXi-LOG`
- 「CDI」タブか「設定」タブの「Bluetoothでつなぐ」→ 一覧から選ぶ（CDIとロガーで1回ずつ）
- 一度つないだ機器は、アプリを開いた時に自動でつなぎ直します（端末によってはボタンを押し直す）
- USB-C でもつながります（Windowsはそのまま。Androidは XIAO ESP32S3 のときだけ）

## 4. 走者とピットをつなぐ

1. 両方で「ピット」タブを開く
2. 同じ「チーム名」と「合言葉」を入れる
3. バイクのスマホは「走者（子機・バイク）」、ピットのPC・スマホは「ピット（親機）」→「参加する」

- スマホの回線で、公開の中継サーバー2か所を通します。中身は合言葉から作った鍵で暗号化
- 走者側のデータ量は 1時間で約20MB
- ピット側からできること：PIT IN、「あと○周で戻れ」、メッセージ、レース開始・終了、給油、CDIのモード・枠・攻め度・手動の上乗せ・学習、マップを書いて枠に入れる
- 走者の「設定 → ピットからの変更を受け付ける」をオフにすると、ピットからは見るだけになります
- **走者のスマホは画面を消さない・アプリを裏にしない**。裏にすると記録と送信が止まり、CDIは0.8秒でフェイルセーフのマップに切り替わります（安全側）

## 5. ファームを書き込む（Arduino IDE）

**Arduino Nano（点火・テスター）**
- ボード「Arduino Nano」、プロセッサ「ATmega328P」（互換品で失敗したら「ATmega328P (Old Bootloader)」）
- ライブラリは要りません
- 書き込む間は、ESP32 とつないでいる TX/RX の線を外す

**XIAO ESP32S3（CDIの通信・ロガー）**
- ボードマネージャで「esp32 by Espressif Systems」を入れる
- ボード「XIAO_ESP32S3」、USB CDC On Boot「Enabled」
- ライブラリマネージャで「ArduinoJson」を入れる

**ふつうのESP32ボード**
- ボード「ESP32 Dev Module」。ピンはスケッチの `#else` の所と、`parts.html` の配線表の「ESP32 DevKit」列

## 6. 最初の手順（この順番で）

1. Nano 2台に書き込む（点火用とテスター用）
2. 昇圧モジュールはつながずに、テスターNanoでCDI Nanoを回す。シリアルモニタで `s` → 表が18°前後ならOK
3. XIAO に通信ファームを入れて Nano とつなぐ → アプリの「CDI」で状態が出ればOK
4. 高電圧部を組む。昇圧の出力を単体で250Vに合わせる
5. スパークテスターで火花を確認
6. 車体に付けて、「CDI → パルサー位置の測定」をオン → アイドルでタイミングライト → 読んだ角度を「パルサー位置」に入れて保存 → オフ
7. 「18度固定」の枠で走る → 問題なければ他のマップへ

**ピックアップの位置について**：3000rpm 以上では、1回転前のパルスから時間を計って、パルサーより前でも点火できます。なので今の位置のままでも使えます。ただ、急加速中の精度はパルサーが一番進めたい角度より前にある方が良いので、余裕があれば 25〜30°BTDC に出してください。3000rpm 未満はパルサー位置より進めません（始動は8°）。

## 7. 注意

- コンデンサには250〜300Vが溜まり、電源を切っても残ります。触る前に必ず抜く（`parts.html` の「高電圧の注意」）
- POSHのCDIは、同じカプラですぐ戻せるようにしておく
- 理論値のマップ・熱補正の温度（攻め：警告245℃・危険270℃）は一般的な傾向からの出発点です。プラグの焼けとピストンを見ながら、実走で詰めてください
- 安全スイッチを閉じると、アプリの指示に関係なく18°固定になります

## 8. ここまでに確かめたこと

- **点火Nano**：マイコンのシミュレーターで実際のファームを動かし、2000〜10400rpm でマップどおりの進角（ずれ0.2°以内）、レブリミット、リアルタイム補正、通信切れ1秒でフェイルセーフ、安全スイッチ、パルサーより進める場合を確認
- **通信ESP32・ロガー**：PC上で実際のファームを動かし、アプリの命令と返事、Nanoへ送る行とチェックサム、GPSの読み取りを確認
- **アプリ**：サンプルで全画面を通し、走者とピットの2台を試験用の中継サーバーでつないで遠隔操作まで確認
- **まだ**：本物の Bluetooth・センサー・高電圧・エンジンでは試していません。最初はベンチテスターと18°固定から
